## 一、最靠谱的入手策略

你已有 Java/Spring Boot 和 Vue3 经验，因此不要从“Go 语法大全”开始。最靠谱路线是：

```text
先跑起来
  -> 看懂请求链路
  -> 做低风险管理接口
  -> 做前端页面联调
  -> 做数据库和配置改动
  -> 再进入 Relay、计费、渠道、任务这些核心域
```

原因：

- 这个项目的难点不在 Go 语法，而在业务链路：Token、分组、渠道、计费、任务、日志。
- 你熟悉 Spring Boot，后端分层思路可以快速迁移到 Gin + GORM。
- 你熟悉 Vue3 + TS，前端部分切到 React 19 + TanStack Router + React Query 的成本可控。
- 一开始不要碰计费、支付、渠道分发、任务轮询这些高风险路径，先从 CRUD/查询/配置类接口练手。

## 二、Java/Spring Boot 到本项目 Go 栈的映射

| Java/Spring Boot 经验 | 本项目对应概念 | 代码位置 |
| --- | --- | --- |
| `@RestController` | Gin Handler 函数 | `controller/` |
| `@RequestMapping` / `@GetMapping` | Gin Router 注册 | `router/` |
| Filter / Interceptor | Gin Middleware | `middleware/` |
| Service Bean | 普通 Go 包函数 | `service/` |
| Entity / Repository | GORM Model + 函数 | `model/` |
| DTO / VO | Go struct | `dto/`、`types/` |
| JPA / MyBatis | GORM v2 | `model/` |
| `application.yml` | 环境变量 + `options` 表 | `.env.example`、`model/option.go` |
| Spring Security | Session/Auth 中间件 | `middleware/auth.go` |
| `ThreadLocal` 请求上下文 | `gin.Context` | 全链路 |
| `@Transactional` | `DB.Transaction(func(tx *gorm.DB) error {})` | `model/`、部分 controller |
| 定时任务 | goroutine + for/sleep | `main.go`、`service/task_polling.go` |
| 统一异常处理 | handler 返回错误 + helper 响应 | `common`、`types.NewAPIError` |

心智模型可以这样迁移：

```text
SpringBoot:
Controller -> Service -> Repository -> DB

当前项目:
router -> middleware -> controller -> service -> model -> DB/Redis
Relay:
router -> middleware(TokenAuth/Distribute) -> controller.Relay -> relay handler -> channel adaptor -> upstream
```

## 四、Go 只需要先学这些

你不需要先把 Go 全学完。按当前项目，先掌握下面这些就够开始改代码。

### 1. 包和文件

Go 没有 Java 那种类路径强约束，但包名很重要：

```go
package controller
```

同一目录下的 `.go` 文件属于同一个 package，可以直接访问同包内的函数和类型。

导入项目内包：

```go
import "github.com/QuantumNous/new-api/model"
```

### 2. struct 相当于 Java class 的数据部分

```go
type Token struct {
    Id          int    `json:"id"`
    UserId      int    `json:"user_id" gorm:"index"`
    Key         string `json:"key" gorm:"type:varchar(128);uniqueIndex"`
}
```

反引号 tag 同时服务 JSON、GORM、校验等框架。

### 3. 方法和函数

普通函数：

```go
func GetTokenById(id int) (*Token, error) {}
```

方法：

```go
func (token *Token) Clean() {
    token.Key = ""
}
```

Go 没有异常，习惯是返回 `error`：

```go
token, err := model.GetTokenById(id)
if err != nil {
    common.ApiError(c, err)
    return
}
```

### 4. 指针

Go 指针在当前项目里很常见：

```go
func UpdateToken(token *model.Token) error
```

经验规则：

- 要修改对象，用指针。
- 可能为空，用指针。
- DTO 中可选数值字段，优先用指针，否则 `0` 会和“没传”混淆。

特别注意：Relay 请求 DTO 中，可选 scalar 字段要用 `*int`、`*float64`、`*bool` 加 `omitempty`，避免显式传 `0` 或 `false` 被丢掉。

### 5. defer

类似 Java `finally`：

```go
defer resp.Body.Close()
```

当前项目里常用于：

- 释放响应体。
- 请求失败退款。
- panic recover。
- 数据库连接关闭。

### 6. goroutine

类似轻量线程：

```go
go model.SyncOptions(common.SyncFrequency)
```

项目中大量后台任务使用 goroutine：

- 配置同步。
- 渠道缓存同步。
- 任务轮询。
- 通知发送。
- 退款异步处理。

不要随便新开 goroutine，除非你清楚生命周期、错误处理和并发安全。

### 7. interface

Go interface 是“隐式实现”。Relay 适配器就是典型例子：

```go
type Adaptor interface {
    Init(info *relaycommon.RelayInfo)
    DoRequest(...)
    DoResponse(...)
}
```

某个 struct 只要实现了这些方法，就自动满足接口，不需要 `implements`。

### 8. JSON 规则

项目规定：业务代码不要直接调用 `encoding/json` 的 marshal/unmarshal。

使用：

```go
common.Marshal(v)
common.Unmarshal(data, &v)
common.DecodeJson(reader, &v)
common.UnmarshalJsonStr(str, &v)
```

已有少量历史代码直接使用 `encoding/json`，新代码按项目规则走 `common` 包。

## 五、项目分层怎么读

### 1. 后端主路径

```text
main.go
  -> router/
  -> middleware/
  -> controller/
  -> service/
  -> model/
```

对应职责：

| 层 | 你应该怎么理解 |
| --- | --- |
| `router` | Spring 的路由表，只注册路径和中间件 |
| `middleware` | 认证、限流、渠道分发、上下文注入 |
| `controller` | 参数绑定、权限边界、响应格式 |
| `service` | 复杂业务逻辑和跨 model 编排 |
| `model` | GORM 表结构、CRUD、事务、缓存 |

### 2. Relay 主路径

```text
router/relay-router.go
  -> middleware.TokenAuth
  -> middleware.Distribute
  -> controller.Relay
  -> relay/*_handler.go
  -> relay/channel/{provider}/adaptor.go
  -> 上游 AI Provider
```

Relay 是项目最核心也最容易踩坑的部分。建议你等完成前几轮练习后再改。

### 3. 前端默认主题主路径

```text
web/default/src
  -> routes/             路由入口，TanStack Router
  -> features/           按业务域组织页面、api、hooks、components
  -> components/ui       基础 UI 组件
  -> components/layout   布局和导航
  -> lib                 axios、工具函数、格式化
  -> i18n/locales        多语言文案
```

优先改 `web/default`。`web/classic` 是旧版 React 18 + Vite + Semi UI，除非明确要兼容旧主题，否则不要优先投入。

## 七、第二阶段：第 2-3 天做低风险后端改动

目标：能新增一个普通管理接口。

推荐练习：新增一个只读状态接口。

### 1. 后端新增接口的标准路径

```text
1. 在 `controller/demo.go` 这类业务文件中写 handler
2. 在 router/api-router.go 注册路由
3. 如需业务逻辑，放 service/
4. 如需查表，放 model/
5. 返回 common.ApiSuccess / common.ApiError
6. 写测试或至少手动 curl 验证
```

### 2. 最小 Controller 模板

```go
func GetSomething(c *gin.Context) {
    userId := c.GetInt("id")

    data, err := service.GetSomething(userId)
    if err != nil {
        common.ApiError(c, err)
        return
    }

    common.ApiSuccess(c, data)
}
```

### 3. 路由注册

在 `router/api-router.go` 合适的 group 中注册：

```go
selfRoute.GET("/something", controller.GetSomething)
```

如果是管理员接口：

```go
adminRoute.Use(middleware.AdminAuth())
adminRoute.GET("/something", controller.GetSomething)
```

### 4. 不要一开始就做这些

第 2-3 天不要改：

- `middleware/Distribute`。
- `service/billing*`。
- `relay/channel/*`。
- 支付回调。
- 数据库迁移主流程。
- 多节点缓存逻辑。

先从查询接口、轻量配置接口、前端展示接口练手。

## 九、第四阶段：第 2 周开始做数据库和配置改动

目标：能安全新增字段、配置项和表。

### 1. 新增字段路线

```text
1. 修改 model 中 struct
2. 确认 gorm tag
3. 确认 SQLite / MySQL / PostgreSQL 兼容
4. 如需特殊迁移，在 model/main.go 迁移逻辑中处理
5. 更新 controller/service DTO
6. 更新前端类型和页面
7. 写 model/controller 测试
```

项目支持 SQLite、MySQL、PostgreSQL，数据库改动要特别谨慎。

### 2. GORM 注意事项

优先使用：

```go
DB.Where("id = ?", id).First(&obj)
DB.Create(&obj)
DB.Model(&obj).Updates(map[string]any{...})
DB.Transaction(func(tx *gorm.DB) error { ... })
```

尽量避免手写 SQL。如果必须手写：

- PostgreSQL 列引用用 `"column"`。
- MySQL/SQLite 列引用用 `` `column` ``。
- 代码里已有 `commonGroupCol`、`commonKeyCol` 处理关键字字段。
- 布尔值差异用 `commonTrueVal`、`commonFalseVal`。

### 3. 新增配置项路线

配置项通常走 `options` 表和 `OptionMap`。

```text
model/option.go
  -> InitOptionMap 设置默认值
  -> updateOptionMap 解析并写入对应 setting/common 变量
controller/option.go
  -> 管理后台读写配置
前端 system-settings
  -> 展示和保存配置
```

配置改动要考虑：

- 默认值。
- DB 中历史值。
- 多节点 `SyncOptions`。
- 前端表单保存格式。

## 十二、推荐练习路线

### 练习 2：给现有列表接口加一个过滤条件

目标：熟悉 controller + model。

候选：

- Token 列表。
- 日志列表。
- 渠道列表。

要求：

- 参数从 query 读取。
- model 层加 `Where`。
- 注意分页。
- 前端加一个筛选输入。

### 练习 3：新增一个简单配置项

目标：理解 `options` 表和热更新。

做法：

```text

```

验证：

- 保存后刷新页面仍存在。
- 重启后仍存在。
- 等待 `SyncOptions` 后其他节点可读取。

### 练习 4：新增一个 model 字段

目标：理解 GORM 和跨数据库兼容。

做法：

```text

确认 AutoMigrate
controller 返回字段

```

注意：

- 不要使用数据库专属类型。
- JSON 内容优先用 `TEXT` 存储。
- 不要写只有 MySQL 能跑的 SQL。

### 练习 5：给一个现有 Provider 加小兼容

目标：进入 Relay，但控制风险。

候选：

- Header 透传。
- 请求字段映射。
- 响应 usage 修正。

要求：

- 先找对应 `relay/channel/{provider}`。
- 写 provider 局部测试。
- 不动公共计费逻辑。

## 十三、开发一个新功能的标准流程

### 1. 后端功能

```text
确认是否已有相似接口
  -> 找 router/api-router.go
  -> 找 controller 同类文件
  -> 找 service/model 同类函数
  -> 设计 DTO
  -> 写 controller
  -> 写 service/model
  -> 注册路由和中间件
  -> 写测试
  -> 手动 curl
  -> 前端接入
```

### 2. 前端功能

```text
确认业务域 features/{domain}
  -> api.ts 加请求函数
  -> hooks 加 React Query
  -> components 加 UI
  -> routes 加页面入口
  -> i18n 加文案
  -> typecheck/build
```

### 3. 数据库功能

```text
确认表关系
  -> model struct
  -> AutoMigrate 或手写兼容迁移
  -> CRUD 函数
  -> controller/service 调用
  -> 测试 SQLite/MySQL/PostgreSQL 兼容性
```

### 4. Relay 功能

```text
确认请求格式
  -> dto
  -> helper.GetAndValidateRequest
  -> relay handler
  -> adaptor
  -> usage/计费
  -> 日志
  -> 重试错误分类
```

## 十四、项目编码规则必须记住

### 1. JSON 使用项目封装

不要新增直接 marshal/unmarshal：

```go
common.Marshal(v)
common.Unmarshal(data, &v)
common.DecodeJson(reader, &v)
common.UnmarshalJsonStr(str, &v)
```

### 2. 数据库必须三库兼容

项目支持：

- SQLite。
- MySQL >= 5.7.8。
- PostgreSQL >= 9.6。

所有表结构和 SQL 要同时兼容。

### 3. 可选请求字段保留显式零值

Relay 请求 DTO 的可选标量字段必须用指针：

```go
MaxTokens *uint `json:"max_tokens,omitempty"`
Stream *bool `json:"stream,omitempty"`
```

不能用：

```go
MaxTokens uint `json:"max_tokens,omitempty"`
```

否则用户显式传 `0` 会被丢掉。

### 4. 不要随意改保护性标识

项目名、组织名、版权、许可证、镜像名、包路径等受项目策略保护，不要做重命名或删除。

### 5. 改前端要补 i18n

默认前端使用：

```text
web/default/src/i18n/locales/{lang}.json
```

新增文案后运行：

```bash
cd web/default
bun run i18n:sync
```

### 6. 改计费表达式先读文档

涉及 `pkg/billingexpr` 或动态/阶梯计费，先读：

```text
pkg/billingexpr/expr.md
```

## 十五、常见坑位

| 坑 | 说明 | 避免方式 |
| --- | --- | --- |
| 忘记 `return` | Go 不会自动中断函数 | `common.ApiError` 后立刻 `return` |
| 误用值传递 | struct 被复制，修改不生效 | 需要修改时用指针 |
| 直接读写 Context key 拼错 | Gin Context 是字符串 key | 优先用 `constant.ContextKey*` |
| DB 只在 MySQL 测过 | PostgreSQL/SQLite 失败 | 用 GORM，少写裸 SQL |
| 直接改 Relay 计费 | 容易多扣/漏扣 | 先理解 BillingSession |
| 忽略 Redis 缓存 | DB 改了但缓存旧 | 调用对应 invalidate/update |
| 前端只改默认语言 | 多语言缺失 | `bun run i18n:sync` |
| 修改 Token DTO 用非指针 | 零值丢失 | 可选 scalar 用指针 |
| 忽略请求体复用 | Relay 重试读不到 body | 使用 `common.UnmarshalBodyReusable` |
| 支付回调重复处理 | 用户多加额度 | 只处理 pending，保持幂等 |

## 十八、每次改代码前的检查清单

后端：

- 这个接口应该放在哪个 router group？
- 需要 `UserAuth`、`AdminAuth` 还是 `RootAuth`？
- 是否需要 `CriticalRateLimit`？
- controller 是否只做参数和响应？
- 业务逻辑是否该放 service？
- DB 逻辑是否该放 model？
- 是否影响 Redis 缓存？
- 是否影响三种数据库兼容？
- 是否需要日志或审计？

Relay：

- 是否影响 Token 额度？
- 是否影响用户额度？
- 是否影响订阅额度？
- 是否影响 usage 解析？
- 是否影响流式响应？
- 是否影响重试？
- 是否影响错误格式？
- 是否需要加入 StreamOptions 支持列表？

前端：

- 是否放在正确 feature 目录？
- 是否复用已有 UI 组件？
- 是否补 i18n？
- 是否通过 typecheck？
- 是否移动端可用？

## 二十、最稳的成长路径总结

最稳路线是：

```text
第 1 步：跑通环境和请求
第 2 步：熟悉 Gin Controller 和 GORM Model
第 3 步：做管理后台小功能
第 4 步：做前端 React 页面联调
第 5 步：做配置和表字段改动
第 6 步：理解 Relay 链路
第 7 步：做 Provider 小兼容
第 8 步：再进入计费、支付、订阅、任务这些高风险域
```

你已有的 Java/Spring Boot/Python/Vue3 经验会非常有帮助。真正需要补的不是“编程能力”，而是三件事：

1. Go 的错误返回、指针、接口、goroutine 习惯。
2. Gin + GORM 在这个项目里的固定写法。
3. 当前项目自己的业务契约：Token、分组、渠道、计费、任务、缓存。

只要按上面的路线走，最先一周就能做稳定的管理端和前端改动，两周左右可以开始接触 Relay 周边，一个月后再进入计费和任务这类核心域会稳很多。
