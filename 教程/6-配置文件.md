# 配置文件与配置项说明

本文基于当前项目源码中的启动流程、`setting` 配置模块、前端构建配置、Docker/CI/Electron 配置整理。项目的配置来源不是单一文件，而是由环境变量、数据库 `options` 表、前端构建文件、容器编排文件和工程自动化文件共同组成。

## 一、配置来源总览

| 配置来源 | 主要文件/模块 | 生效阶段 | 作用 |
| --- | --- | --- | --- |
| 命令行参数 | `common/init.go` | 后端进程启动 | 控制监听端口、日志目录、版本输出等启动行为 |
| `.env` / 环境变量 | `.env.example`、`common/init.go`、`main.go`、`model/main.go` 等 | 后端进程启动和运行期 | 控制数据库、Redis、缓存、限流、任务、日志、分析脚本、第三方端点等 |
| 数据库配置 | `model/option.go`、`setting/config/*`、`setting/*` | 启动加载，运行时可更新 | 存在 `options` 表中，供管理后台修改，覆盖全局运行时开关和业务参数 |
| 前端构建配置 | `web/default/*config*`、`web/classic/*config*` | 前端开发/构建 | 控制构建工具、代理、路径别名、UI 组件规范、TypeScript、Lint、i18n 等 |
| 容器/部署配置 | `Dockerfile`、`Dockerfile.dev`、`docker-compose*.yml` | 镜像构建和容器运行 | 控制多阶段构建、运行环境、数据库/Redis 服务、端口和卷挂载 |
| 桌面端配置 | `electron/package.json` | Electron 打包 | 控制桌面应用的入口、打包产物、平台资源和安装器 |
| CI/发布配置 | `.github/workflows/*` | GitHub Actions | 控制 Docker 镜像、二进制 Release、Electron 构建、PR 检查、同步发布 |
| 国际化资源 | `i18n/locales/*.yaml`、前端 `src/i18n/locales/*.json` | 后端/前端运行期 | 提供多语言消息文案，不是开关类配置，但会影响界面和 API 返回文案 |

## 二、后端配置加载流程

1. `main.InitResources()` 先尝试 `godotenv.Load(".env")`，本地存在 `.env` 时会注入环境变量。
2. `common.InitEnv()` 解析命令行参数和环境变量，初始化密钥、数据库路径、缓存、限流、Relay 超时等进程级配置。
3. `model.InitDB()` 根据 `SQL_DSN` / `SQLITE_PATH` 初始化主数据库，并执行迁移。
4. `model.InitOptionMap()` 先写入默认 OptionMap，再从 `options` 表加载覆盖值。
5. `config.GlobalConfig.Register()` 注册的分层配置，以 `模块名.字段名` 的 key 存入 `options` 表，例如 `general_setting.docs_link`。
6. `model.SyncOptions(common.SyncFrequency)` 周期性从数据库刷新配置，默认 60 秒。
7. Redis 启用后，内存缓存也会被强制启用，并按 `SYNC_FREQUENCY` 同步。

## 三、启动参数

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--port` | `3000` | 后端 HTTP 服务监听端口；若设置环境变量 `PORT`，最终启动端口优先使用 `PORT` |
| `--version` | `false` | 打印当前版本后退出 |
| `--help` | `false` | 打印启动帮助后退出 |
| `--log-dir` | `./logs` | 日志目录；启动时会转为绝对路径，不存在时自动创建 |

## 五、数据库 `options` 表中的分层配置

分层配置由 `setting/config.ConfigManager` 管理，写入 `options.key` 时使用 `模块名.字段名`。复杂类型会以 JSON 字符串存储，bool/int/float/string 按字符串存储。运行时调用 `model.UpdateOption()` 后会同步更新内存配置。

## 十四、配置之间的主要关联

| 关联 | 说明 |
| --- | --- |
| `SQL_DSN` / `SQLITE_PATH` -> `options` 表 | 数据库先初始化，之后所有后台可变配置才从 `options` 表加载 |
| `REDIS_CONN_STRING` -> `MEMORY_CACHE_ENABLED` | Redis 启用后，内存缓存会被强制启用 |
| `SYNC_FREQUENCY` -> OptionMap/渠道缓存 | 控制配置和缓存同步周期，过短会增加数据库/Redis 压力 |
| `theme.frontend` -> Web 路由 | 主题配置决定后端托管 default 还是 classic 前端，并影响旧路径重写 |
| `ServerAddress` -> OAuth/Passkey/回调 | 外部访问地址影响第三方登录、Passkey RP ID/Origins、支付回调展示 |
| `general_setting.quota_display_type` -> 额度展示 | 新版额度展示配置替代旧的 `DisplayInCurrencyEnabled` |
| `billing_setting` + 倍率配置 | 表达式计费可覆盖传统倍率计费；更新后会清理价格缓存 |
| `FORCE_STREAM_OPTION` + 渠道支持列表 | 对支持 stream options 的渠道请求 usage，影响流式计费准确性 |
| `fetch_setting` + 文件/图片下载 | SSRF 防护配置约束远程资源拉取和代理类能力 |
| `VITE_REACT_APP_SERVER_URL` + dev proxy | 只影响前端开发服务器代理，不影响后端生产路由 |

## 十五、维护注意事项

1. 运行时业务配置优先通过管理后台写入 `options` 表，除数据库、Redis、端口、密钥、构建版本等启动级配置外，不建议频繁改环境变量。
2. 分层配置新增字段时，应在对应 `setting/*` 结构体中添加 JSON tag，注册到 `config.GlobalConfig` 后会自动按 `模块名.字段名` 存取。
3. 传统 OptionMap 配置新增时，需要同时处理默认值、数据库加载、`updateOptionMap()` 的类型转换和运行时变量同步。
4. 多节点部署必须固定 `SESSION_SECRET` / `CRYPTO_SECRET`，并明确 `NODE_TYPE`，避免 slave 执行不该执行的后台任务。
5. 数据库配置要同时兼容 SQLite、MySQL、PostgreSQL，避免只在某一种数据库可用的配置迁移或原生 SQL。
6. 前端仅 `VITE_` 前缀变量会进入构建产物，不要把后端密钥放入前端环境变量。
7. `TLS_INSECURE_SKIP_VERIFY`、`fetch_setting.allow_private_ip`、`passkey.allow_insecure_origin` 这类安全放宽配置应只用于受控测试环境。
